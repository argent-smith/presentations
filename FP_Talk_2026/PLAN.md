# Тезисный план доклада

**"Древняя магия в повседневном коде: пять принципов функционального программирования в пяти языках"**

Тайминг: 30 минут. Вопросы — отдельно.

---

## Введение (3 мин)

**Провокация.** Вы уже пишете функциональный код — и давно. `array.map`, `filter`, замыкания в
обработчиках событий, `const` вместо `let`. Это не мода и не случайность.

**Тезис.** ФП — не Haskell и не монады из учебника. Это пять конкретных свойств, у которых один
общий знаменатель: **декларативность**. Код описывает задачу, а не управляет потоком выполнения.

**Карта доклада.** Пять свойств × пять языков с разной философией:

| Язык       | Философия                        |
|------------|----------------------------------|
| OCaml      | академическая чистота            |
| Scala      | JVM-прагматизм                   |
| Python     | простота и доступность           |
| JavaScript | вездесущесть                     |
| Rust       | системная безопасность без GC    |

Почему именно эти пять: максимальный разброс подходов при минимальном наборе языков.

## Свойство 1. Функции как значения (5 мин)

**Тезис.** Функция — объект, значение. Её можно передать, сохранить в переменную, вернуть из другой функции.
Это не синтаксический сахар — это фундамент для абстракции. Это также больше, чем процедура — это полноправный гражданин языка.

**Ключевые идеи:**

- Функция высшего порядка — функция, принимающая или возвращающая функцию. `map`, `filter`,
  `reduce` — не магия стандартной библиотеки, а прямое следствие этого свойства.
- Замыкание — функция, захватившая окружение. В JS это было с самого начала; в Rust за это отвечает
  компилятор и явные `move`-семантики.
- Каррирование — превращение `f(a, b)` в `f(a)(b)`. OCaml делает это по умолчанию; в Python
  и JS требует явного кода или библиотек.

**Контрасты между языками:**
- OCaml: каррирование по умолчанию — `multiply 3` уже функция, не вызов. HOF (`List.map`, `List.filter`) — стандартная идиома. Замыкания — через `fun` и `let`.
- Scala: HOF через коллекционное API (`.map`, `.filter`). Замыкания — `val adder = (x: Int) => x + n`. Каррирование — явное через параметры в отдельных списках или `.curried`.
- Rust: HOF через итераторы (`.map()`, `.filter()`). Замыкания явны: `Fn`/`FnMut`/`FnOnce` — различие по владению в сигнатуре. Каррирование — через возврат замыкания, нет нативного синтаксиса.
- Python: HOF — `map()`, `filter()` или comprehensions. Замыкания — через вложенные `def`. Каррирование — `functools.partial`, не синтаксис языка.
- JavaScript: HOF — `.map()`, `.filter()`, `.reduce()` — нативная идиома. Замыкания — основа языка с самого начала. Каррирование — стрелочные функции, без специальных средств.

**Вывод.** Разница не в том, поддерживается ли свойство — оно поддерживается везде. Разница в том,
насколько язык делает это идиоматичным.

## Свойство 2. Ссылочная прозрачность (5 мин)

**Тезис.** `f(x)` всегда возвращает одно и то же для одного `x`. Это не ограничение — это гарантия.
Предсказуемый код — тестируемый код.

**Ключевые идеи:**

- Чистая функция: нет скрытых зависимостей, нет побочных эффектов. Результат определяется только
  аргументами.
- Следствия: мемоизация работает корректно; порядок вычислений не важен; параллелизм безопасен.
- Практика: в реальных программах эффекты неизбежны (IO, сеть, время). Вопрос не "избегать
  эффектов", а "изолировать их".

**Контрасты между языками:**
- OCaml: чистота — умолчание; функция без `ref`/IO чиста по конструкции. Мемоизация безопасна для любой чистой функции. Эффекты явно изолированы (`ref`, `Printf`).
- Scala: чистота — по соглашению в "обычном" Scala. Эффекты изолируются через `IO`-монаду (cats-effect): `IO[Double]` ≠ `Double`. Параллелизм поверх чистых вычислений — безопасен.
- Rust: чистота — по соглашению, не по конструкции. `&` vs `&mut` ограничивает мутацию в сигнатуре. Отсутствие shared mutable state → параллелизм без гонок (borrow checker).
- Python: чистота — вопрос дисциплины. Мемоизация — `@functools.lru_cache`, работает только на чистых функциях, но чистоту не проверяет. Изоляция эффектов — соглашение.
- JavaScript: замыкания легко захватывают внешнее состояние — нечистота незаметна. Мемоизация — вручную или через библиотеки. Изоляция эффектов — архитектурный паттерн (Redux и подобные).

**Вывод.** Чистота — спектр, а не бинарное свойство. Каждый язык находится в разной точке этого
спектра, и это сознательный выбор дизайна.

## Свойство 3. Иммутабельность (5 мин)

**Тезис.** Данные не изменяются — создаются новые версии. `const` — это не иммутабельность;
это запрет на переприсваивание переменной.

**Ключевые идеи:**

- Иммутабельность по умолчанию vs по соглашению vs по принуждению компилятора.
- Persistent data structures: структурное переиспользование памяти при создании "новой версии".
  Изменить один элемент списка из 10 000 — не значит скопировать 10 000 элементов.
- Практические следствия: thread safety, отсутствие defensive copies, упрощение reasoning.

**Контрасты между языками:**
- OCaml: иммутабельно по умолчанию; `ref` — явное исключение. Списки и деревья — persistent структуры. Thread safety чистых значений — бесплатна.
- Scala: `val` — иммутабельно, `var` — мутабельно. Persistent коллекции (Vector, List) со structural sharing в stdlib. Копирование через `.copy()` на case class — не копирует всё дерево.
- Rust: `let` — иммутабельно, `let mut` — явная мутация; компилятор запрещает случайную мутацию. Thread safety гарантирована на этапе компиляции через `Send`/`Sync`. Persistent DS нет в stdlib — ownership предлагает другие гарантии.
- Python: примитивы иммутабельны (`int`, `str`, `tuple`), коллекции — мутабельны (`list`, `dict`). Persistent DS — через сторонние библиотеки. Defensive copies — обычная практика.
- JavaScript: `const` запрещает переприсваивание, но не мутацию объекта. `Object.freeze` — поверхностное. Persistent DS — `Immutable.js` или аналоги. Thread safety — не проблема в single-threaded модели браузера, но актуальна для SharedArrayBuffer.

**Вывод.** Rust и OCaml делают мутацию явной аномалией. Python и JS оставляют это программисту.
Scala — посередине. Чем явнее мутация, тем проще читать код.

## Свойство 4. Декларативность (5 мин)

**Тезис.** Декларативный код описывает **что** нужно получить, не **как** это вычислить.
Это не украшение, это разделение уровней абстракции в самом рассуждении о программе.

**Ключевые идеи:**

- Императивный цикл: "создай переменную, проверяй условие, инкременть индекс". `map`: "применить
  функцию к каждому элементу". Второе — объявление намерения, первое — микроменеджмент механизма.
- Декларативность — сквозной принцип: SQL (`SELECT ... WHERE`) декларативен. HTML декларативен.
  Регулярные выражения декларативны.
- Связь с остальными свойствами: декларативный стиль возможен именно потому, что функции — значения
  и данные иммутабельны. Уберите одно — декларативность рассыплется.

**Контрасты между языками:**
- OCaml: pipeline `|>` выражает намерение как цепочку шагов. Паттерн-матчинг заменяет ветвления, рекурсия — циклы. Нет
  соблазна написать императивно: инструментов для этого меньше. Язык толерантен к императивным привычкам, но поощряет декларативность.
- Scala: коллекционное API (`.map`, `.filter`, `.sum`) читается как постановка задачи. `for`-comprehension — синтаксический сахар над `flatMap`, скрывает цепочку связываний. Параллельные коллекции (`.par`) — декларативность масштабируется без изменения кода.
- Rust: ленивые итераторы декларативны и дешевы — компилятор разворачивает в эквивалент цикла. Явный `.collect()` фиксирует намерение о материализации. Императивный цикл — доступен, но итераторы — идиоматичнее.
- Python: comprehensions идиоматичны и читаемы. `for`-цикл — тоже идиоматичен; выбор за программистом. Нет принуждения к декларативному стилю — оба подхода в норме.
- JavaScript: цепочки `.map().filter().reduce()` — идиоматичны. Pipeline-оператор `|>` — в стадии proposal. `Promise` и `async/await` — декларативны по природе.

**Вывод.** Декларативный код — это документация намерений. Читающий видит "что", а не путается
в деталях "как".

## Свойство 5. Выражения вместо инструкций (5 мин)

**Тезис.** Если `if` возвращает значение — код становится компонуемым. Нет необходимости в `return` или `void`,
нет "функции по умолчанию как процедуры".

**Ключевые идеи:**

- Инструкция выполняется ради эффекта. Выражение вычисляется в значение.
  В expression-oriented языках граница стёрта: всё — выражение.
- Компонуемость: выражение можно вложить туда, где ожидается значение — передать аргументом,
  присвоить, вернуть. `f(if x > 0 then a else b)` — норма. Временные переменные-носители
  промежуточного результата не нужны; код читается как одно связное вычисление, а не как
  последовательность команд с побочным эффектом присваивания.
- Следствие: нет необходимости в `return` (OCaml, Rust — последнее выражение — результат).
  Нет незаполненных веток `if`. Компилятор проверяет полноту перебора.
- Pattern matching — вершина этого подхода: деструктуризация + возврат значения + проверка
  полноты перебора компилятором.

**Контрасты между языками:**
- OCaml: всё — выражение; `return` не существует. `if/then/else`, `match`, `let ... in` — возвращают значение.
  Компилятор проверяет полноту перебора в `match` — забытая ветка вызывает ошибку компиляции.
- Scala: `if/else` и `match` — выражения. Компилятор предупреждает о `match` без охвата всех вариантов. Sealed trait + match гарантирует охват всех вариантов.
- Rust: expression-oriented по дизайну; блок `{ ... }` возвращает значение последнего выражения. Точка с запятой превращает выражение в инструкцию (sic!). `match` — выражение, полнота перебора обязательна.
- Python: `if` — инструкция; тернарный оператор — единственное выражение-ветвление. `match` (3.10+) — инструкция, не возвращает значение. Statement-oriented с точечными workaround'ами.
- JavaScript: `if` — инструкция, тернар — выражение. `switch` — инструкция. Нет проверки полноты перебора. TypeScript частично закрывает это через discriminated unions, но не полностью.

**Вывод.** Разница expression vs statement — это разница между "результат этого кода — значение"
и "этот код что-то делает, но результат неизвестен". Первое — компонуемо по природе.

### 1. Функции как значения

**Задача:** создать функцию-умножитель с заданным коэффициентом и применить её к списку.

```ocaml
(* OCaml: каррирование по умолчанию *)
let multiply factor x = x * factor
let triple = multiply 3
let result = List.map triple [1; 2; 3; 4; 5]
(* result: [3; 6; 9; 12; 15] *)
```

```scala
// Scala: функция — объект Function1
val multiply: Int => Int => Int = factor => x => x * factor
val triple = multiply(3)
val result = List(1, 2, 3, 4, 5).map(triple)
// result: List(3, 6, 9, 12, 15)
```

```rust
// Rust: замыкание с явным владением
fn multiply(factor: i32) -> impl Fn(i32) -> i32 {
    move |x| factor * x
}

let triple = multiply(3);
let result: Vec<i32> = vec![1, 2, 3, 4, 5].into_iter().map(triple).collect();
// result: [3, 6, 9, 12, 15]
```

```python
# Python: замыкание явное, каррирование через functools
from functools import partial

def multiply(factor, x):
    return factor * x

triple = partial(multiply, 3)
result = list(map(triple, [1, 2, 3, 4, 5]))
# result: [3, 6, 9, 12, 15]
```

```javascript
// JavaScript: замыкание — родная идиома
const multiply = factor => x => factor * x;
const triple = multiply(3);
const result = [1, 2, 3, 4, 5].map(triple);
// result: [3, 6, 9, 12, 15]
```

**Акцент для доклада:** OCaml не требует лямбды — `multiply 3` уже является функцией.
Rust требует `move`, потому что замыкание захватывает `factor` — и это видно в сигнатуре.

### 2. Ссылочная прозрачность

**Задача:** функция вычисления скидки — чистая и нечистая версии, контраст.

```ocaml
(* OCaml: чистая функция *)
let apply_discount rate price =
  price *. (1.0 -. rate)

(* Применение *)
let discounted = apply_discount 0.1 100.0
(* discounted: 90.0 — всегда, при любых условиях *)
```

```scala
// Scala: чистая функция vs IO-монада для эффектов
def applyDiscount(rate: Double, price: Double): Double =
  price * (1.0 - rate)

// Эффекты изолированы явно:
import cats.effect.IO
def applyDiscountWithLog(rate: Double, price: Double): IO[Double] =
  IO.println(s"Applying $rate discount") *> IO.pure(applyDiscount(rate, price))
```

```rust
// Rust: &mut сигнализирует о мутации; чистая функция — без &mut
fn apply_discount(rate: f64, price: f64) -> f64 {
    price * (1.0 - rate)
}
// Компилятор не позволит случайно изменить price внутри функции без явного &mut
```

```python
# Python: разница между чистой и нечистой версией — только дисциплина

# Нечистая (зависит от внешнего состояния):
current_discount = 0.1
def apply_discount_impure(price):
    return price * (1 - current_discount)

# Чистая:
def apply_discount(rate: float, price: float) -> float:
    return price * (1 - rate)
```

```javascript
// JavaScript: та же история — чистота не гарантируется

// Нечистая:
let taxRate = 0.2;
const priceWithTax = (price) => price * (1 + taxRate); // зависит от внешнего

// Чистая:
const applyDiscount = (rate) => (price) => price * (1 - rate);
```

**Акцент для доклада:** Scala делает эффекты видимыми в сигнатуре — `IO[Double]` ≠ `Double`.
Python и JS полагаются на программиста. Rust ограничивает мутацию, но не гарантирует чистоту.

### 3. Иммутабельность

**Задача:** обновить одно поле записи — показать разницу между мутацией и структурным копированием.

```ocaml
(* OCaml: record — иммутабелен по умолчанию *)
type user = { name: string; age: int }

let user = { name = "Alice"; age = 30 }
let older_user = { user with age = 31 }
(* user не изменился; older_user — новое значение *)
```

```scala
// Scala: case class с copy
case class User(name: String, age: Int)

val user = User("Alice", 30)
val olderUser = user.copy(age = 31)
// user неизменён
```

```rust
// Rust: struct update syntax; let без mut — иммутабельно
#[derive(Debug)]
struct User { name: String, age: u32 }

let user = User { name: String::from("Alice"), age: 30 };
let older_user = User { age: 31, ..user };
// let mut нужен явно для мутации — компилятор не даст забыть
```

```python
# Python: dataclass(frozen=True) или NamedTuple
from dataclasses import dataclass, replace

@dataclass(frozen=True)
class User:
    name: str
    age: int

user = User("Alice", 30)
older_user = replace(user, age=31)
# user.age = 31 → TypeError: frozen dataclass
```

```javascript
// JavaScript: spread-оператор (поверхностное копирование)
const user = Object.freeze({ name: "Alice", age: 30 });
const olderUser = { ...user, age: 31 };
// user.age = 31 → в strict mode: TypeError; иначе молча игнорируется
```

**Акцент для доклада:** `{ user with age = 31 }` в OCaml и `user.copy(age = 31)` в Scala —
это не копирование всей структуры в памяти. Структурное переиспользование. В JS `Object.freeze` —
только первый уровень вложенности.

### 4. Декларативность

**Задача:** из списка заказов получить сумму скидок для заказов дороже 100, применив скидку 10%.

```ocaml
(* OCaml: pipeline с |> *)
let total_discount orders =
  orders
  |> List.filter (fun o -> o.price > 100.0)
  |> List.map (fun o -> o.price *. 0.1)
  |> List.fold_left ( +. ) 0.0
```

```scala
// Scala: коллекционное API
def totalDiscount(orders: List[Order]): Double =
  orders
    .filter(_.price > 100.0)
    .map(_.price * 0.1)
    .sum
```

```rust
// Rust: ленивые итераторы, нет промежуточных аллокаций
fn total_discount(orders: &[Order]) -> f64 {
    orders.iter()
        .filter(|o| o.price > 100.0)
        .map(|o| o.price * 0.1)
        .sum()
}
```

```python
# Python: comprehension + sum
def total_discount(orders):
    return sum(
        o.price * 0.1
        for o in orders
        if o.price > 100.0
    )
```

```javascript
// JavaScript: цепочка методов массива
const totalDiscount = (orders) =>
  orders
    .filter(o => o.price > 100)
    .map(o => o.price * 0.1)
    .reduce((acc, d) => acc + d, 0);
```

**Акцент для доклада:** Rust-версия компилируется в тот же машинный код, что и императивный цикл —
ленивые итераторы оптимизируются. Декларативность здесь бесплатна.

### 5. Выражения вместо инструкций

**Задача:** классификация числа — вернуть метку без промежуточной переменной.

```ocaml
(* OCaml: match — выражение, if — выражение, нет return *)
let classify n =
  match n with
  | n when n < 0 -> "negative"
  | 0            -> "zero"
  | _            -> "positive"
```

```scala
// Scala: match — выражение
def classify(n: Int): String = n match {
  case n if n < 0 => "negative"
  case 0          => "zero"
  case _          => "positive"
}
```

```rust
// Rust: match — выражение; точка с запятой убирает значение (!)
fn classify(n: i32) -> &'static str {
    match n {
        n if n < 0 => "negative",
        0          => "zero",
        _          => "positive",
    }  // без точки с запятой — значение возвращается
}
```

```python
# Python: match (3.10+) — инструкция, не выражение
# Workaround: тернарный оператор или dict-lookup
def classify(n: int) -> str:
    return "negative" if n < 0 else "zero" if n == 0 else "positive"

# match в Python не возвращает значение:
# label = match n: ...  → SyntaxError
```

```javascript
// JavaScript: if — инструкция; приходится использовать тернар или IIFE
const classify = (n) =>
  n < 0 ? "negative" : n === 0 ? "zero" : "positive";

// Или через объект-словарь, но не идиоматично для этой задачи
```

**Акцент для доклада:** в OCaml и Rust компилятор проверяет полноту перебора в `match`.
Забыть ветку — ошибка компиляции, не баг в рантайме. В Python и JS это невозможно по дизайну.
